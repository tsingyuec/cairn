# 小节处理约定

沿用 video2blog-content 的“系列目录 → 小节任务 → 独立博客 → 验收回写”方式。每条知识脉络就是一个系列，README 是目录与进度的唯一来源。**本文件提供执行约定，不意味着当前已经要求生成全部小节。** 开始前还需读取 [学习单元粒度规则](granularity.md)，不能把现有目录的每个词或每个字段机械变成一次采集。

## 小节与产物

- README 中章为 `## 1`，节为 `### 1.1`，小节为带稳定锚点的列表行：`- 1.1.1 标题 <a id="b01-1-1-1"></a> [WAITING]`。
- 正文路径：`content/<分组>/<分类>/<系列>/X.Y_<节>/X.Y.Z_<小节>/<博客标题>.md`。
- 配图：小节目录下 `assets/<博客标题>/`；一支视频形成独立博客。默认每小节选择 1–3 篇互补材料，完成以目标覆盖为准，不以篇数验收；不把多支视频拼成一篇。
- 文章与小节是多对多关系：一篇博客只有一个规范位置，但可由其他小节的 `README.md` 导读引用；不重复改写整场报告。
- 导读必须写 `## 学习目标覆盖`，逐项说明已有正文覆盖什么，并给出项目内真实博客链接。只链到另一个目录或写“内容见上”不能验收。
- 物理目录不另分“章”。节/小节目录名由 `scripts/sections.py list` 给出，去掉标题里的复用链接注记。
- 中间结果：`_work/<分组>/<分类>/<系列>/X.Y.Z_<小节>/`，可含选题单、视频、字幕、抽帧和图文稿；不进版本库。
- 公共概念仍只在主归属脉络展开，引用指向该系列 README 的稳定小节锚点，不依赖博客文件名。

## 状态与认领

`WAITING → PROCESSING → DONE / ABORT`；意外中断且无可验收产物时可回到 WAITING。

1. 重读指定 README 及目标小节所在章节中位于其前的 `[REUSE]` 条目，确认所需基础与学习目标后，在用户指定范围内选择 WAITING。`[REUSE]` 没有独立状态，不能认领或完成；其链接是知识要求，不是额外写作授权，不自动认领上游任务。
2. 由主会话执行精确认领：

```bash
python3 scripts/sections.py list --track B01 --status WAITING
python3 scripts/sections.py claim --track B01 --section 1.1.1
```

3. 工具比较旧状态，只修改目标行并立即重读确认；同一脉络状态写入使用文件锁。认领失败应重读，不抢占 PROCESSING。
4. 主会话是共享 README 的唯一写者。工作者只写自己的 `_work/` 和小节正文，不改 README、不认领其他小节、不再委派。
5. 写作和检查完成后，由主会话验收，再执行 `finish`。工具只检查基本产物存在，不代表内容已达标。

```bash
python3 scripts/sections.py finish --track B01 --section 1.1.1
python3 scripts/sections.py release --track B01 --section 1.1.1
python3 scripts/sections.py abort --track B01 --section 1.1.1
```

`finish` 要求规范目录下有非空正文，或有带目标覆盖说明并链接项目内既有正文的导读。脚本只验证存在性，覆盖是否成立仍需人工验收；`release/abort` 遇到这些产物会拒绝，需先核对。不得整体重写 README 来更新进度。

## 单条和批量模式

- 单条模式：仅处理用户指定的一个小节，完成即结束。
- 批量模式：只有用户明确授权委派时才启用；每批最多两个小节，每个工作者只负责一个，上一批全部验收后才能认领下一批。不以任务量大为由自动派生子智能体。
- 对同批相邻主题明确知识边界和已用视频，避免选中相同视频的大段重复内容。
- 启动或运行失败要报告，不静默换其他执行工具或模型。

派发时应给出：系列 README、编号和完整标题、主线与边界、规范输出路径、相关基础引用、已用视频、处理要求及 video2blog skill 路径。

## 视频探索与成稿

1. 认领后先在 `_work/` 选题单写：核心问题、必须覆盖、不在范围、前置复用、已有博客及候选材料。已有学习目标不能降低为“提到几个关键词”。
2. 检查本项目已有博客和相邻小节的选题单，登记视频 URL/ID、已用时间区间、博客规范路径与实际覆盖；能复用的先复用，不以禁止同视频再引用为由退而选择劣质替代视频。
3. 根据小节主题构造中英文关键词，在 Bilibili/YouTube 探索；先按题目和简介剔除不相关素材。
4. 对最有希望的 5–8 个候选抓字幕，按覆盖深度、系统性和初学者可读性排序；同等质量 Bilibili 优先。
5. 默认选择 1–3 支互补视频，建立“目标—实际段落—博客”的覆盖对应。共用一场报告不意味着要合并教学目标；一项若包含完整模型的多套机制，应先报告粒度问题，不能以综述降格验收。材料过多时由主会话判断拆分或合理例外；过少时不能凑数。素材不足、与邻节重复或目标过粗时先报告，不让工作者自行改目录。
6. 使用外部 [video2blog skill](https://github.com/tsingyuec/video2blog-skill) 的下载、抽帧、字幕、图文稿通顺化和成稿流程。默认安装位置为 `~/.agents/skills/video2blog/SKILL.md`；也可由 `VIDEO2BLOG_SKILL` 指定目录。
7. 未安装时先提示/取得安装授权，不复制来源项目的 cookies、账号、私有配置或工作缓存。不得凭记忆跳过 skill。
8. 视频博客只基于该视频的图文稿写作；配图必须逐张看过，单次最多读三张；关键结论带原片时间戳。
9. 生物学、模型和原始资源的事实审查仍遵守本项目约定。原始论文/发布用于核验；概览播客、相似模型或通用工具视频不能替代专有机制、精确字段或内部数据证据。科学核验与视频忠实整理不一致时明确列为待核对，不把视频中的绝对化表述升级为事实。
10. 无合适材料时先报告缺口、已检索范围与官方/授权资料方案；只有主会话确认该轮确实无合格素材时才 ABORT，并记录原因。不能仅因没有中文或遇到限流就判定无素材。

默认沿用视频处理方式。用户若另行要求论文/官方文档专题，可沿用小节目录和状态，但必须明确素材类型和一手引用，不伪造视频、图文稿或时间戳。

## 验收

- 逐项核对选题单的目标覆盖：具体解释或案例在哪一篇/哪一段，哪些目标尚未覆盖。达到三篇、文章很长、标题相似都不代表已完成。
- 内容确实对应当前小节；公共基础复用，不重复铺开整条邻近脉络；复用导读的引用正文须实际覆盖本节目标。
- 每支视频博客独立、图文稿可回溯、时间戳与配图有效、术语适合初学者。
- 执行外部 video2blog skill 的图片和时间戳检查，以及本项目公式检查：

```bash
python3 scripts/validate.py
node scripts/check/check_md_math.mjs content/<分组>/<分类>/<系列>/X.Y_<节>/X.Y.Z_<小节>
python3 site/build_site.py --check
python3 site/build_site.py
mkdocs build --strict
node scripts/check/check_katex.mjs build/site --recursive
```

- 确认站点侧栏能找到文章、源链接被正确改写、引用锚点可跳转。验收后再 finish；状态变化后再跑目录校验。
- 无合格素材才用 ABORT，不把下载失败、限流、预算耗尽或工具中断冒充“无素材”。

## 中断与残留

- PROCESSING 且正文已落位：先验收，不直接抢做或覆盖；合格后补 DONE。
- 无正文但工作目录最近 60 分钟仍有变动：跳过，视为可能仍在执行。
- 无正文且工作目录不存在或超过 60 分钟无变动：主会话确认无活动执行后 release；不自动删除用户或其他工作者的文件。
- 超时/异常需说明；两条连续失败时先判断共同原因，不立即重复启动。
