# 扩充知识目录

## 开始前

1. 以本 skill 目录为基准，项目根目录是 `../../..`。阅读根 README、`content/README.md` 和拟修改分类的 README。
2. 检查 Git 工作区，不覆盖用户改动。除非用户要求，本流程只更新目录，不自动展开正文、不改相邻业务项目、不提交或部署。
3. 新主题先回答：**它解决什么科学问题，输入输出是什么，与哪些既有概念或资源相连？**
4. 必须读取 [学习单元粒度规则](granularity.md)和[整合式章节目录规则](curriculum.md)：先检查知识覆盖、精确前置和认知负担，再验证素材，不按模型名、名词数或视频数划分。
5. 若用户要求实际处理小节，读取 [小节处理规则](processing.md)：沿用视频知识库的小节认领、节/小节落位和验收状态。扩充目录本身不自动认领或生成正文。

## 1. 核对来源与实际对象

### 新模型

阅读原始论文、官方仓库/文档及明确版本的能力说明，记录：

- 任务、输入、输出与生成/预测对象；单点、分布、序列、坐标、图不能混用。
- 架构与目标：序列模型、图模型、等变网络、潜变量、扩散、流等；不能只从模型名或“基础模型”宣传推断。
- 条件信息、训练语料、评价协议及适用边界。
- 与同任务模型的共同机制和新增机制，区分模型家族、具体版本和部署包装。

来源业务仓库只提供发现线索，不作为科学事实的最终依据。没有公开资料的内部模型，明确标注资料性质和未核实能力，不虚构论文或官方地址。

### 新数据资源

找到**原始提供方及官方发布**，记录其实体、实验设计、测量值、元数据、标识符、版本、证据来源、许可与引用要求。

- 区分原始读段、一手实验、官方处理矩阵、跨研究整理资源及门户/检索服务。
- 沿资源本身的来源链理解数据，不把 biodata 的筛选结果、整合站点、表名或 API 当成新原始数据库。
- 本体发布方与 OLS 一类检索服务分开；计数量化产品与推断结果分开。
- 内部实验没有公共原站时如实说明；外部参照库不自动成为内部实验的来源。
- 官方全集、本地已有范围和模型有效样本量分别描述，不以软件许可证推断数据许可。

无法核实的事实标注“待核对”及所需证据；若核心对象尚不清楚，先询问用户，不用猜测补齐分类。

## 2. 决定放在哪里

按下列顺序判断，优先复用，不按对象名称机械建目录：

1. **已有小节足够表达**：只补对象入口、原始资料或关联链接，不新增重复概念。
2. **同一科学问题下有特有知识**：扩展现有 P/D 脉络，按需要增加节/小节。
3. **多个专题反复依赖的新概念**：将可独立讲授的概念放入 B/M，共享基础中不夹带模型专有参数。
4. **独立问题无法自然纳入已有主线**：新建脉络，说明与近邻的边界。
5. **单条叶子脉络扩充后将达到 100 个小节**：才需要拆分该脉络；接近上限时提前评估。B01、B02 等各算一条，分类总和不受 100 限制。不能为控制汇总数而压缩教学，也不要求各条小节数相近。按独立科学问题拆分，不按供应商或版本号拆分。

主归属只有一个，其他关系用引用表达。目录归属不等于硬性前置依赖，避免把推荐阅读写成互相循环的必读条件。

### 目录与编号

- 生物学公共概念：`content/基础知识/生物学/<主题>/README.md`，B 编号。
- 通用模型方法：`content/基础知识/模型方法/<主题>/README.md`，M 编号。
- 模型家族与科学任务：`content/专题知识/模型/<主题>/README.md`，P 编号。
- 原始资源与数据问题：`content/专题知识/数据资源/<主题>/README.md`，D 编号。

新编号取对应系列当前最大编号加一；不用回收编号，不因移动目录修改编号。目录名使用能独立理解的中文主题，保留必要专有名词。现有分类足够时不增加新层级；确需改变分类规则时同步更新导航、模板、校验器和测试。

## 3. 编写或扩充目录

新建脉络使用 [README 模板](template.md)；判断示例见 [扩充实例](examples.md)。

每条脉络必须包含：知识主线、范围与边界、组织与素材策略、章—节—小节目录、学习出口、原始资料和父级导航。专题目录本身就是完整课程：所需通用知识以 `[REUSE]` 小节在使用处编入，与专题扩展小节交错，不另设学习路线或阶段；复用必须链接具体叶子小节，不能要求通读整门 M01 等上游课。新建或实质修改的小节应附简短学习目标；保留单元须在写作选题单中明确覆盖边界。

**标题与学习问题分开**：标题直接写知识主题和核心知识点，例如“scANVI 标签置信度：概率校准、未知类型与稀有类型”；不写“标签迁移怎样识别未知类型和不可靠标签”。用核心问题确定粒度，但把问句、学习结果和不展开的范围写进“学习目标”，不要直接把问题句当标题。已有清晰的名词性标题无需统一加冒号，也不能为罗列术语而扩大实际覆盖。

先检查知识完整性和深度：一个可独立理解与验收的问题、明确前置和不在范围；不是按逗号拆词，也不把复杂度不同的方向硬压成相近小节数。再检查素材实际覆盖。尚未搜索/核对的素材须标为待验证，不能承诺每个小节都一定存在 1–3 支合适视频。

**专题完整性检查**：先列科学问题的方法谱系与验证链，再选择模型作深入案例，不能用业务平台已注册模型充当领域边界。区分方法、机制与学习衔接三种缺口，不能只加模型名或链接了基础就认定覆盖完整。

**模型深度检查**：先列该模型实际的表示、核心模块、训练监督、推理/采样与评价，再对应到目录中的具体单元。不是机械地为每一项各建一节，但不能用一个“模型机制”标题包住所有内容，或只留输入输出和风险提醒。已有标题出现模型名不等于机制已经覆盖。经典方法以真实算法与假设检查，不硬套神经网络模板；不公开的架构保留证据缺口，不猜测补齐。

- 按“对象/问题 → 表示与证据 → 特有机制 → 比较评价 → 局限与验证”选择必要内容，不机械凑齐相同章节。
- 每条小节须有独立学习目的；不能为了凑到 100 而拆句，或为了低于 100 把整门学科塞入一个标题。
- 公共概念正文主归属 B/M 的**具体小节**，但这些概念须以 `[REUSE]` 小节进入专题的章节顺序，并说明阅读深度和本地用途；不能只列整门课作前置。复用条目不新增 WAITING 或正文副本。平行模型和数据专题用“关联”连接。
- 警告、字段、单位和版本说明优先并入同一机制/资源判读案例的验收项；不是每句话都独立找视频。
- 同一视频博客允许跨小节规范引用，不得因为路径不同就重复整理整场报告；也不得为避免重复视频而把编码、训练、采样等独立机制压在一项里。
- 模型专题讲任务、机制和证据，不写镜像、端口或部署步骤；数据专题讲原始资源，不复制本地字段/查询接口手册。
- 只有带编号与状态的列表行计为小节，总数必须在 1–99；章用 `## 1`，节用 `### 1.1`。
- 新小节采用 `- 1.1.1 知识主题：关键机制或术语 <a id="p12-1-1-1"></a> [WAITING]`。章、节前也保留显式锚点；不依赖中文标题自动生成的锚点。
- README 是进度的唯一来源。未处理内容全部 WAITING，不能把“已建目录”标成 DONE；无需为空小节预建正文目录。
- 未来正文按 `<系列>/X.Y_<节>/X.Y.Z_<小节>/<博客标题>.md` 落位，不增加物理章目录。复用已有正文时，小节可放带 `## 学习目标覆盖` 和真实正文链接的 `README.md` 导读，不复制正文。
- 相对链接从当前 README 位置计算，目标必须留在本项目内。原始网站用外链，不用相邻业务仓库路径作长期依赖。
- 不链接尚未存在的正文文件。资料待确认时标注，不伪造“官方来源”。

修改已有目录时尽量在已有节末追加小节或在篇末追加章节，保留原编号和锚点。移动、重命名或拆分时搜索所有入链并同步修复；如需重编号，明确给出迁移映射和影响，不能悄悄重排。

## 4. 同步所有入口

1. 更新所属分类 README 中的脉络链接、条数和小节数。
2. 更新上级“基础知识/专题知识”的分类统计。
3. 更新 `content/README.md` 的总量、对应脉络说明/覆盖对象和必要的串联路线。
4. 若总量或项目结构变化，更新根 README；不要让分类索引与项目入口互相矛盾。
5. 补充确实有帮助的关联与学习出口。避免给所有已有脉络添加无意义的回链。

## 5. 校验与科学审查

在项目根目录执行：

```bash
python3 scripts/validate.py
python3 -m unittest discover -s tests -v
python3 site/build_site.py --check
python3 site/build_site.py
mkdocs build --strict
git diff --check
```

站点依赖与公式检查见根 README；目录校验只依赖标准库。脚本必须通过，但不能替代人工检查：

- 模型架构与版本是否确有原始证据，是否把置信度当成实验成功率？
- 是否沿科学关系归类，而非照抄业务目录？
- 是否把原始站点、官方整理资源、镜像和二次整合区分清楚？
- 新概念是否已在别处讲过，是否应提取公共基础？
- 复用链接是否不仅“能打开”，还真正对应所需概念？
- 仅看标题能否明确知道核心知识点，而不用从“如何／怎样／为什么”中猜范围？标题没有擅自增加正文不准备覆盖的术语？
- 新手能否直接从当前 README 依次完成必要基础、本地机制与验证，而不用自行从几门大课筛内容？分支是否分别列最小基础和跳读标准？专业缩写能否解释？
- 章节是否因内容而组织，而不是每个新模型套一份空洞模板？是否仍有一项承担整节甚至整章的机制、以减少任务为名遗漏关键内容？

若有外链未联网核实或科学事实待核对，在交付中说明，不将静态校验通过表述为事实验证通过。

## 交付内容

简要列出新增对象、原始来源、归类/复用/新建/拆分的理由、修改路径、共享引用、更新后规模与校验结果。涉及原有编号变化时另列受影响引用与修复范围。
