# 脉络检查清单

逐项打勾；不适用的项写“不适用”，不要留空。每发现一个问题，记录：位置（代码/编号/锚点）、事实、影响、建议动作、证据。

## 0. 快照与范围

- [ ] 目标脉络代码、路径、所属分类已记录。
- [ ] 当前小节总数、自有任务数、REUSE 数、最大编号已记录。
- [ ] 当前状态分布已记录（通常全部 WAITING）。
- [ ] Git 工作区状态已记录；审查期间没有改文件。
- [ ] 已读根 README、content/README、分类 README。
- [ ] 已读目标 README 全文，不只看目录。
- [ ] 已读 granularity.md、curriculum.md。
- [ ] 已读上一轮复审报告/明细，知道哪些问题已落地、哪些未落地。
- [ ] 已读所有 REUSE 目标小节。
- [ ] 已读相邻脉络 README（同科学问题、同分类、上下游）。

## 1. 主线

- [ ] 能用一句话写出该脉络的科学主线。
- [ ] 能列出主线的必要环节（对象 → 表示/证据 → 机制 → 评价 → 验证）。
- [ ] 每个环节在目录中都有对应章/节，或明确说明为什么不需要。
- [ ] 没有把“模型清单”“字段清单”“部署步骤”当成主线。
- [ ] 能说清该脉络不覆盖什么（范围边界）。
- [ ] 能说清与相邻脉络的分工（谁负责哪个科学问题）。

## 2. 章、节、小节结构

- [ ] 每章对应一个完整环节，而不是一个模型或一个数据表。
- [ ] 每节标题能覆盖其下所有小节；没有标题与内容不符。
- [ ] 没有空节；没有只有 1 个小节且可以并入相邻节的碎片节。
- [ ] 章/节/小节编号连续，锚点唯一。
- [ ] 小节总数 < 100（含 REUSE；按叶子脉络计）。
- [ ] 没有把同一机制拆成字段级小节，也没有把多个独立机制压在一个小节。
- [ ] 没有“模型资料/版本说明/免责声明”独立成节，挤占教学单元。

## 3. 前置与顺序

- [ ] 数学/统计概念先于使用。
- [ ] 生物学概念先于模型机制。
- [ ] 文件格式、标识符、坐标约定先于资源判读。
- [ ] 评价协议、切分、基线先于“模型好坏”的结论。
- [ ] 没有前向引用（“见后文”不算解决）。
- [ ] 没有循环前置。
- [ ] 没有跨章跳跃：先讲结果，再补定义。
- [ ] 每个“前置”都指向具体叶子小节，不是整门课。
- [ ] 移动/插入后，后续编号和入链已同步。

## 4. 主线完整性

按“可命名的缺失单元”检查，不按数量。

- [ ] 从对象到结论的每个必要环节都有单元。
- [ ] 方法谱系不只列少数模型：有经典/统计/非神经路线或对照方法。
- [ ] 机制深度足够：表示、训练目标、采样/推理、评价至少各有落点。
- [ ] 评价与验证齐全：基线、切分、校准、外部验证、失败模式、实验衔接。
- [ ] 生物学/数据前提齐全：实验单位、测量条件、标识符、版本、许可、受控访问。
- [ ] 每个“仍缺”都能写出：缺什么、插在哪、为什么必需、证据是什么。
- [ ] 没有为了凑数制造缺口；主线闭合时明确写“否”。

### B/M 脉络额外检查

- [ ] 概念定义能落到可观察对象，而不是只给术语。
- [ ] 机制能解释“为什么”，不只给流程图。
- [ ] 计算/测量单元有输入输出、假设、误差来源。
- [ ] 与下游 P/D 的接口清楚：哪些概念会被 REUSE，哪些在本脉络深入。
- [ ] 没有把某个具体模型的专有参数写进公共基础。

### P 脉络额外检查

- [ ] 任务定义清楚：输入、输出、条件、评价对象。
- [ ] 方法谱系完整：至少覆盖一类经典/非神经路线，不只当前热门模型。
- [ ] 模型案例讲特有机制，不套统一模板。
- [ ] 每个模型有训练/推理/评价的至少一个独特点。
- [ ] 有失败模式、适用域、证据边界。
- [ ] 有实验验证或下游决策的衔接。
- [ ] 专有模型内部细节没有从相似模型推断。

### D 脉络额外检查

- [ ] 原始提供方、官方发布、版本、许可、引用要求清楚。
- [ ] 区分原始读段、官方处理矩阵、跨研究整理资源、门户/检索服务。
- [ ] 标识符、坐标、版本、实体关系能落到具体记录。
- [ ] 有数据使用边界：开放/受控、再分发、隐私、临床限制。
- [ ] 有任务适配：资源能支持什么模型/分析，不能支持什么。
- [ ] 没有把本地二次处理站点当成原始数据库。

## 5. REUSE

- [ ] 来源是自有 B/M 任务小节，不是整门课、不是另一个 REUSE、不是 P/D 专题。
- [ ] 链接指向具体叶子锚点，能打开。
- [ ] 来源标题与当前用途一致。
- [ ] 放在使用之前。
- [ ] 同一脉络内没有重复引用同一来源。
- [ ] 学习目标说明“取什么、怎么用”，不是模板句。
- [ ] 计入本脉络规模，但没有被算作任务、没有被认领或标状态。
- [ ] 如果本脉络有特有扩展，保留自有任务；如果只是重复 B/M，改 REUSE 或收窄。
- [ ] REUSE 没有形成链（A 复用 B，B 又复用 C）。

## 6. 标题

- [ ] 名词性知识主题，不是问句。
- [ ] 没有“如何/怎样/为什么/什么/哪里/从何/读懂/学会”等词。
- [ ] 没有多个独立机制用逗号硬拼。
- [ ] 没有为统一格式强行加冒号；短标题可以没有冒号。
- [ ] 标题没有 overclaim 专有模型内部细节。
- [ ] 标题能让人直接知道核心知识点，不用猜范围。
- [ ] 标题中的编号/关联链接没有过期。

## 7. 学习目标

- [ ] 每个自有任务都有学习目标。
- [ ] 3–5 个可验收检查点。
- [ ] 使用“说明/比较/判断/识别/把……联系起来”等可检验动词。
- [ ] 包含边界或失败模式，不只复述标题。
- [ ] 没有“掌握「…」的基本定义和关键关系”“给出与本节范围一致的解释或案例”“细节以原节为准”等模板句。
- [ ] 目标中的编号引用指向当前小节。
- [ ] 目标没有引入标题未覆盖的新范围。

## 8. 重复与错位

- [ ] 同一机制在 B/M 与 P/D 没有各写一遍；有唯一主归属。
- [ ] 同一模型在多个专题没有重复讲同一模块。
- [ ] 评价单元没有夹在训练节；数据任务没有挂在标识章；许可没有放在字段说明里。
- [ ] 没有“只有字段/命令/端口/部署步骤”的伪知识单元。
- [ ] 重复单元已改为 REUSE、收窄或删除，并说明理由。

## 9. 范围与出口

- [ ] 范围声明与目录实际内容一致。
- [ ] 新增对象（别构口袋、mRNA 设计、受控访问、许可等）已写入范围。
- [ ] 排除对象（gnomAD 等）已写明边界。
- [ ] 前置知识声明真实：没有“无需上游”但大量 REUSE 的矛盾。
- [ ] 学习出口有依据，不是随手链接相邻专题。
- [ ] 需要用户决定的范围问题已列为 C 类，没有自行决定。

## 10. 证据边界

- [ ] 区分“目录级判断”与“科学事实已核实”。
- [ ] 没有把 README/规则阅读说成论文、代码或视频已读。
- [ ] 专有模型内部细节没有官方证据时标证据缺口。
- [ ] 资源许可、版本、使用协议未核对时标“待核对”。
- [ ] 没有把静态校验通过说成科学正确或教学充分。

## 11. 报告

- [ ] 结论先写“主线是否闭合：是/否”。
- [ ] 整块缺失与局部缺口分开。
- [ ] 每个缺口有位置、单元名、理由、证据、建议动作。
- [ ] A/B/C/D 分级清楚。
- [ ] 已落地项没有重复报告；未落地项明确标出。
- [ ] 报告模板字段完整。
- [ ] 如果结论是“完整”，明确写“否，未发现整块缺失”。

## 12. 修复后（仅授权修复时）

- [ ] 先预览再 apply。
- [ ] 每轮独立 ledger，不覆盖历史映射。
- [ ] 新 ledger 已追加到 `tests/test_migration.py`。
- [ ] 所有入链已修复。
- [ ] 每脉络小节数、分类统计、根 README 已同步。
- [ ] 空节已删除或补单元。
- [ ] 标题/目标中的编号引用已同步。
- [ ] 验证命令全部通过。
- [ ] 没有自动提交、推送、部署或生成博客。
